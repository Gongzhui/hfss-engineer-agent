# 求解等待接口（2026-09-06）

问题：start 返回任务编号之后，Agent 用 sleep 与 status 自行安排等待。
考试记录中有 396 次 50 秒 sleep，但只有 23 次状态查询。工具层可以提供
等待完成的语义，不能替宿主保证长时间挂起模型或恢复已经结束的对话。

## 接口

`analyze_wait(job_id, timeout_s=45)`：异步 MCP 工具，等待范围 0–120 秒。
沿用 status 的完整返回结构，增加 `wait_reason`、`waited_s`、`timed_out`。

- `terminal`：任务已结束，必须检查 `job.state` 区分成功和失败。
- `timeout`：本次等待到期，求解保持运行，下一次继续用同一编号。
- `unverified`：恢复的运行记录缺少当前 worker 确认，立即返回 recovery_hint。
- 无效编号或等待时长返回错误；不会创建求解。
- 取消 MCP 请求只取消等待协程，不取消求解；取消求解仍需 analyze_cancel。

内部每 250 ms 异步检查内存状态，不在等待中持有锁，不在每个 tick 读取
HFSS 消息。入口和出口沿用非阻塞 status 快照及单飞后台消息刷新。
这是程序内的状态检查，不需要模型参与每次检查。

## 宿主与恢复边界

默认 45 秒给常见 60 秒工具超时留余量；调用者应根据实际宿主 deadline
选择更长或更短的等待。当前 Codex 配置 180 秒无需修改。
支持后台工具等待的宿主可保持同一调用；外层主动 yield 时依然可能恢复模型。
没有 wait 的旧服务器仍可用低频 status。没有新增守护进程或自动唤醒机制。

任务记录已持久化，但求解 worker 仍属于原 MCP 进程。重启后不得用已有
曲线或部分结果推断完成。Skill、README 与两处考场说明同步此边界。
本次没有修改历史考试记录、冻结文件、工程模型或客户端全局配置。

## 验证

最终回归：114 passed，3 个 real_aedt 测试未运行；新增及修改的 app/test 通过 Ruff。

- 单元测试：完成/失败提前返回、状态并发、超时重试、取消等待、恢复的
  未验证记录、非法时长、缺失任务、公开工具 schema。
- 真实 stdio MCP 子进程 + ClientSession：模拟 worker，验证等待期间 status
  仍响应、请求取消后 worker 继续完成、随后等待取得完成状态。
- 保留原有 COM 阻塞回归测试，防止进度接口再次进入同步 COM。
- 此轮未启动真实 HFSS 求解，传输测试中的求解明确为模拟任务。
